## 3. 新增/更新的探针断言

- `panel-probe ②a`：卡面代码 chip 文案 `代码 +3 −1`
- `panel-probe ⑤`：技能库「删除」按钮 `data-variant` 必须是 `danger`（防止映射再退化）
- `panel-probe ⑥`：`[data-empty-block]` 高度 ≤64；「KPI 落单」判据改为「最后一行只有一张**且宽度不足整行 60%**」
  （横跨整行的收口卡不算落单）
- `panel-probe --width/--height`：视口可调，窄窗（900px）也跑一遍

## 4. 还留在 backlog 的（按性价比）

1. **看板列宽**：1440 屏 8 列时默认 200px/列，只放得下 7 列，卡片仍偏挤；「适应宽度」开关存在但默认关。要不要默认开，是产品选择。
2. **两套保存条**：设置 18 个分区各自一个保存条（测试执行/成本预算甚至一页三处），容易漏存；ui-ux-pro-max 的「unsaved-change warning」还没做。
3. **抽屉「测试」页**：三条测试线各一组「跑这层 / 不适用」，按钮语言重复；可以收成每层一个行内动作组 + 一个统一「本层不适用」说明。
4. **交付物/需求矩阵**：状态与来源同一层级、表格无筛选（11-22 审计 P2 原样）。
5. **diff 视图增强**（功能而非排版）：复制路径/复制 diff、只看某次提交、有 MR 时跳 GitLab 的 files 视图、按文件搜索。

## 5. 结论

按 unslop 判级仍是 **Light slop**，但已经只剩「信息密度」问题，不再是「AI 味」问题：
emoji 图标清零、危险操作有红、空态不再占版面、窄窗 KPI 不落单。剩余项都属于信息架构与交互增强，
不该在这一轮顺手改。

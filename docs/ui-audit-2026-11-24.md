## 3. 新增/更新的探针断言

- `panel-probe ②a`：卡面代码 chip 文案 `代码 +3 −1`
- `panel-probe ⑤`：技能库「删除」按钮 `data-variant` 必须是 `danger`（防止映射再退化）
- `panel-probe ⑥`：`[data-empty-block]` 高度 ≤64；「KPI 落单」判据改为「最后一行只有一张**且宽度不足整行 60%**」
  （横跨整行的收口卡不算落单）
- `panel-probe --width/--height`：视口可调，窄窗（900px）也跑一遍
- `panel-probe ③b`：需求矩阵筛选（输入后计数 2/2 → 1/2）
- `panel-probe ④g`：设置页未保存（文本改过 → `data-settings-dirty=1` + 黄色横幅；脏着切分区 → 先确认 → 「丢弃并切换」）
- `panel-probe ⑦`：复制路径 / 复制内容按钮存在（真卡）

## 5. 结论

按 unslop 判级仍是 **Light slop**，但已经只剩「信息密度」问题，不再是「AI 味」问题：
emoji 图标清零、危险操作有红、空态不再占版面、窄窗 KPI 不落单；本轮还把 backlog 的五项一起落了地
（看板列宽默认、设置未保存提醒、测试页动作、矩阵/交付物筛选、diff 复制与 MR 跳转）。
剩下的只有「按提交过滤 diff」这类需要后端按 sha 出 diff 的增强。

## 6. 还剩什么（明确不做 / 待排期）

到这里「复审能直接改的」都改了；下面这些是**有意的取舍或需要另一轮**，不是漏掉的 bug：

- **设置 18 面的保存条本身**：只加了「未保存提醒」，没有把 18 个分区合成一个统一保存动作；一页多处保存（测试执行/成本预算）仍在。
- **需求矩阵行内编辑 / 批量覆盖验收条件**：本轮只做了筛选；矩阵里改功能点/验收条件仍要进编辑表单。
- **需求文档改版 → 受影响用例自动标复跑**：`/requirement/impact` 能列影响面，自动把用例重置为待执行还没接。
- **版本审批可重复记录**：同一版本可以点多次审批（每次留一条记录），没有做幂等/撤回。
- **GitLab 真令牌端到端**：仍只有 mock 验证（上一轮审计 #12 的遗留），需要真实令牌/项目。
- **老审计的纯视觉项**：项目页首屏空白、权限审计页过长、数据备份页回滚与导出同权重 —— ✅ 本轮已做（见 §7）。
- **数据问题**：`REQ-2026-007` 标了已交付但没有验收签字（存在 .218 台账里，不是代码）。
- **流程**：PR 未合并、版本号/CHANGELOG/tag 未动、本地 GUI 未重启——按规矩等用户确认。
